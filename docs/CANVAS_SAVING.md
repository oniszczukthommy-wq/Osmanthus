# 画布保存与多标签冲突

MV 画布使用乐观并发控制。每份工程快照带有 `canvasRevision`，目录记录同时返回 `revision`。两者由服务端更新，客户端保存时必须携带它读到的版本。

- 新工程省略 `canvasRevision` 或传 `0`，首次保存返回 `1`。
- 更新已存在的工程，提交快照的版本必须等于当前目录版本；成功后返回新版本。
- 内容未改变的打开/激活操作不增加版本。
- 旧记录没有版本字段时按 `0` 读取，无须批量修改用户文件；首次实际更新升级为 `1`。
- 旧版本保存返回 HTTP `409`、`code: "CANVAS_CONFLICT"`，不会覆盖目录、当前工程或歌曲关联缓存。

`PUT /api/project` 和用于离页保存的 `POST /api/project` 使用相同校验。客户端必须从成功响应的 `record.revision` 或 `project.canvasRevision` 更新本地基线；若请求期间又发生编辑，只更新基线，不能丢弃新增编辑。

`POST /api/canvas-projects/:id/rename`、`archive` 和 `restore` 的请求体需带 `revision`；重命名另带 `title`。项目列表和详情响应均包含版本。新建、复制和导入副本创建独立 ID，副本版本从 `1` 开始。

发生保存冲突后，前端保留本页工程并暂停重复自动保存，提供：

1. **另存本页副本**：将本页内容保存为独立画布，保留另一页面的原工程。
2. **下载本页备份**：导出可再次导入的工程 JSON。
3. **备份并刷新**：先写入当前标签页的浏览器会话存储，再打开服务端最新版；随后可把备份另存副本。会话存储写入失败时，不会执行刷新。会话备份不是服务器长期存档，关闭标签页前应另存或下载。

歌曲交接重复导入以画布目录为准，避免落后的歌曲缓存覆盖新编辑。后台代码 MV 完成时也检查它启动时的版本；若画布已改变，已生成的视频仍登记在历史版本中并可下载，工程不被覆盖，任务响应带 `saveConflict: true`。从历史版本继续会创建副本。

无示例音频的空白自由画布允许保存、重命名、归档及选取真实音乐。付费故事规划和音视频制作仍要求真实音频，不借用空白画布占位绕过来源检查。

当前并发模型为一个本机 MV 服务、多个浏览器标签页；目录内读取、检查版本及原子替换同步执行，不提供多个服务进程共写同一数据目录的分布式锁。
