# 工程提交与可重建预览缓存

轨道开关、片段编辑、撤销、重做和恢复历史版本，先把候选状态写入独立临时 JSON，刷新文件并原子替换 `project.json`，成功后才切换内存状态。写入、刷新或替换失败时，当前 revision、音频、撤销位置和历史记录保持原样；不会在刷新页面后出现一个并未保存的“幽灵版本”。缓存失效和清理发生在提交之后，清理失败不会将已保存的修改误报为失败。

在服务器 `.env` 设置 `MUSIC_PREVIEW_CACHE_MAX_BYTES=536870912` 可配置**每个工程**的可重建声部预览目标大小，默认 512 MiB。设为 `0` 仅保留当前必要预览及正在读取的文件，不会禁止播放或导出。该值不是全部歌曲、模型、素材和导出的磁盘总限额。

只清理符合全部条件的文件：已登记声部的 `<声部ID>-<16位内容摘要>.wav`，具有匹配的 `.peaks.json` 元数据，且二者均为工程目录内的普通文件。原曲、源分轨、生成声部、人声候选、项目 JSON、历史和导出目录都不在清理范围；未知文件、无法校验的旁路文件和符号链接也不自动删除。

清理按最近使用顺序淘汰旧预览，在工程打开、提交编辑、生成预览以及结束读取时执行，不启动常驻清理线程。最近读取时间保存在 peaks 文件的修改时间中，重启后仍可从磁盘识别缓存。被清理的历史预览可以在撤销或恢复版本时按原始音源和编辑记录重新生成。

当前版本所有有效声部和 HTTP 正在读取的文件受到保护。保护集本身超过目标时允许暂时超限，不能为了满足数字而删除当前播放需要的文件。HTTP 使用覆盖完整响应的读取租约；已加载的编辑器音频在浏览器内存中播放，不依赖缓存文件继续存在。WAV/MP3/ZIP 导出从冻结的工程音频状态渲染，不依赖这类可清理预览。

工程状态接口的 `preview_cache` 包含 `target_bytes`、`bytes`、`protected_bytes`、`over_target` 和本轮 `removed_files`；清理受权限或配置问题阻止时附带 `cleanup_error`。这些统计只覆盖可校验的预览缓存，不包括未知文件。目标是安全的工作集上限，不是整个工程目录的硬配额。

读取租约在当前音乐服务进程内协调，适用现有单实例启动方式。不要同时启动多个音乐服务进程修改同一个工程目录。清理缓存不会删除工程备份，也不能代替独立备份。

隔离回归入口为 `test_project_storage`：模拟写入、刷新和替换失败，核对编辑/撤销/重做/恢复原子性；小容量下连续编辑、LRU、真实慢 HTTP Range 读取、全新进程启动、撤销重建、冻结导出状态，以及原曲/导出/未知文件/符号链接保护。测试仅使用临时合成音频，不调用模型或读取用户歌曲。
