# 调用限额与安全恢复

适用于本机单用户音乐/MV 工作台和经过授权的临时朋友体验。以下规则用于限制新供应商调用、保护下载目录和安全恢复已有歌曲，不提供多租户隔离，也不表示其余审查发现已经全部修复。

## 1. 音乐与 MV 文字调用的次数限额

把需要调整的变量写入服务器根目录 `.env`，重启服务生效。独立运行 MV 时，使用其启动时加载的环境文件。浏览器不能修改服务器限额。

| 设置 | 默认值 | 含义 |
| --- | ---: | --- |
| `MUSIC_TEXT_DAILY_LIMIT` | 60 | 音乐侧写词、灵感与对话等文字请求，每 UTC 日的供应商尝试次数 |
| `MUSIC_SONG_DAILY_LIMIT` | 6 | 音乐侧新生歌请求，每 UTC 日的供应商尝试次数 |
| `MUSIC_ARTWORK_DAILY_LIMIT` | 6 | 音乐侧歌曲封面请求，每 UTC 日的供应商尝试次数 |
| `MUSIC_PAID_TOTAL_LIMIT` | 300 | 音乐侧上述类别共享的累计供应商尝试次数 |
| `MUSIC_PAID_RATE_PER_MINUTE` | 12 | 音乐侧上述类别共享的最近 60 秒次数限制 |
| `MUSIC_PAID_MAX_CONCURRENT` | 2 | 音乐侧同时进行的供应商请求上限 |
| `MUSIC_DRAFT_MAX_WORKERS` | 2 | 音乐侧同时运行的待确认歌词任务数上限，防止排队线程无限增长 |
| `MV_TEXT_DAILY_LIMIT` | 40 | MV 规划、对话等文字请求，每 UTC 日的供应商尝试次数 |
| `MV_TEXT_TOTAL_LIMIT` | 300 | MV 文字请求累计供应商尝试次数 |
| `MV_TEXT_RATE_PER_MINUTE` | 8 | MV 文字请求每个 UTC 分钟桶的次数限制 |
| `MV_TEXT_MAX_CONCURRENT` | 2 | 同一视频服务进程内同时进行的文字请求上限 |

这些值是 **供应商尝试次数，不是人民币，也不是成功作品数**。一次用户操作可能调用多次文字模型、分别生成两首歌及各自封面。每次真正准备向供应商发出新请求前都要占用额度；失败、超时、结果不确定的尝试也保留计数，网络回退到 curl 再发一次同样计一次。轮询已有音乐任务与下载已有音乐不属于新生歌请求。

设为 `0` 表示禁止相应新调用，不表示无限制。音乐侧所有类别还受共享累计、频率和并发限制。MV 文字与音乐有**独立账本**，同一模型账号在两个服务中使用时，不能把任一账本看作账号的完整支出。朋友也会使用本机的对应额度。视频服务按当前单实例部署使用，并发上限不代表多实例全局并发控制。

每日额度在 **00:00 UTC（北京时间 08:00）**进入新的一天；累计额度不会每天或重启后清零。限制启用前的历史调用不会补记，不追溯供应商账户以往费用。最终计费以供应商账单为准，仍应在供应商账户配置额度与余额提醒。

已有 `MV_IMAGE_BUDGET_CNY`、`MV_VIDEO_BUDGET_CNY` 等金额预算保持原有口径，与新增次数限额同时生效。`MV_DISABLE_MODELS=1` 仍关闭 MV 模型调用；次数限额不改变这一开关。

## 2. 账本保留与限额错误处理

- 音乐默认账本：`music-workbench/.local/paid-usage.sqlite3`。可用 `MUSIC_PAID_USAGE_DB` 指向本机固定的完整文件路径。使用默认路径时不要设置此变量；不要把它设为空字符串。
- MV 文字默认账本：`mv-studio/data/text-usage/`，或自定义 `MV_DATA_DIR` 下的 `text-usage/`。
- 重启会保留已用次数。迁移电脑或更换源码目录时，关闭相关服务后，连同工程一起迁移账本；使用独立默认目录的第二份安装不会自动继承第一份的计数。
- 达到限额时先核对调用类别、剩余次数和供应商原任务。若确实要继续，再由本机使用者调整 `.env` 后重启。不要连续点击生成，也不要删除账本来解除限制。
- 账本无法安全读取/写入时停止新的受保护调用，先检查磁盘空间、权限和运行日志。保留原文件排查；不要覆盖成空账本继续付费。

账本记录是限额执行状态，不是完整财务报表、工程备份或权限系统。删除账本、切换新数据目录或重新安装后使用空账本都会失去原计数，因此不能把它当作可抵抗本机管理员修改的供应商硬性账单上限。

## 3. 损坏生歌任务的恢复

启动时读取历史任务会逐个校验。损坏、缺失或不一致的候选记录，不再假定“未提交过”并自动重新生歌：

1. 保留原始坏文件；在对应任务目录尽可能写入 `recovery-error.json` 旁路错误记录。如果磁盘只读或已满，错误记录可能无法写入，仍停止该任务的自动恢复。
2. 将该候选/批次标为需要核对，不再自动发出新的付费生成请求。其他正常历史歌曲、媒体与任务继续加载。
3. 先保存该任务目录、错误记录及现有媒体，再核对供应商的原任务 ID、生成状态和已经付费的结果。不要删除坏记录后用新请求替代原任务。
4. 确认来源与状态后再修复记录或恢复原媒体。本轮没有提供一个能忽略坏记录、强制重新付费的恢复按钮。

该保护针对生歌任务恢复，不能代替全部工程与素材的独立备份，也不保证任意其他类型的损坏文件都能自动修复。

## 4. 音频与导出下载目录

新旧音轨和导出下载路由都只接受服务器生成的单个文件名和对应媒体后缀。Windows 盘符、UNC、反斜杠、备用数据流、设备名、目录跳转和额外编码被拒绝；文件解析后的父目录必须与允许的媒体目录一致，符号链接不能把下载引向目录外。

正常音轨 WAV/MP3、工程导出 WAV/MP3/ZIP 和 Range 读取保持可用。受限规则不是全站文件授权系统：临时对外访问仍应走好友网关，不要直接公开本机原始服务端口。

## 5. 回归检查范围

Windows 和 Linux CI 执行音乐付费计数/并发、歌词重试、候选批次恢复、受限下载以及 MV 文字/HTTP 回归。媒体测试使用临时文件和合成音频；模型测试替换供应商响应，不提交真实付费任务。完整曲目听感、真实供应商当前可用性及低配置电脑表现仍需另行验收。
