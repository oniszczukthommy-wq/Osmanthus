# 工程可靠性与回归门槛

本轮处理工程审查 R4–R10，沿用本机单实例、多个浏览器标签的运行范围。

- **画布保存**：快照携带版本号，旧版本保存返回冲突；本页编辑可以另存副本或下载备份。后台成片撞上更新时保留成片，不覆盖新画布。见 [画布保存说明](CANVAS_SAVING.md)。
- **音乐写盘与预览**：编辑、撤销和恢复先完成原子写盘再替换内存；可重建预览按每工程的容量目标回收，保护当前声部和打开的读取。见 [工程存储说明](PROJECT_STORAGE.md)。
- **预算锁**：仅自动回收能确认持有者已经退出的本机锁。旧的无主锁须停止相关服务后用本机恢复工具隔离，任务和已占预算保留。见 [恢复步骤](../mv-studio/docs/budget-lock-recovery.md)。
- **媒体处理**：FFprobe/波形提取改为异步子进程，默认同时 2 个、最多排队 8 个；单次运行上限 20 秒，排队上限 30 秒。超过承载量返回 `503 MEDIA_BUSY`，不创建无上限的处理线程。文件未改变时复用分析结果，内存缓存最多 64 项。上传仍会等待本次处理完成，但不会为此阻塞整个 HTTP 服务。
- **本机访问**：音乐和 MV 服务验证实际监听端口的 `127.0.0.1` / `localhost` Host，以及请求 Origin；校验作用于读写和媒体请求。好友网关先完成公开入口认证、Origin 校验，再以固定本机身份转发，不透传外部的 Host、Origin 或浏览器 Fetch Metadata。

`MV_MEDIA_CONCURRENCY` 可设为 1–8，`MV_MEDIA_QUEUE_LIMIT` 可设为 0–32。`MUSIC_PREVIEW_CACHE_MAX_BYTES` 默认 536870912，表示每工程可重建预览的目标容量，不是全部素材的硬配额；正在使用的必要文件可能超过目标。原曲、不可重建的生成素材和导出文件不属于缓存清理范围。

## CI 与主分支

Windows 2022 / Ubuntu 24.04 的同一工作流包含音乐创作确认、双方案防重、任务恢复、费用计次、磁盘失败回滚、下载及 Host 校验，以及 MV 图片/视频/配音预算、持久去重、锁恢复、画布版本冲突和真实音视频编码。供应商响应由测试替身提供，不使用用户账户和余额。

没有配置可选的本地语音、视觉模型和音视频夹具时，对应真实模型测试会明确跳过；CI 不会自动下载模型，也不能把这些跳过项当作模型效果已验收。

`main` 的必需检查为 GitHub Actions 的 `portable (windows-2022)`、`portable (ubuntu-24.04)`，要求目标分支保持最新，管理员同样受约束。新改动应先推到 `codex/…` 分支（或发起 PR），让同一提交通过检查后再合入；不能用上一个提交的绿灯代替当前代码验证。配置通过 GitHub API 设置，仓库内的 YAML 本身不能强制分支保护。

该门槛只覆盖已配置测试。它不保证真实供应商永久可用、不替代作品备份，也不是完整渗透测试或所有第三方依赖的安全证明。
