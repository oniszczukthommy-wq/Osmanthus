# 预算登记锁恢复

图片、视频和配音在同一个 MV 数据目录中分别保留自己的预算账本。登记任务时的锁很短，不覆盖模型生成或媒体下载过程。

新版锁记录主机、PID 和唯一持有者标识。只有同一主机的持有者 PID 已明确退出时，服务才会自动清理该持有者的锁；进程仍在运行、PID 被复用、权限不足或主机不同都会保守阻止新提交。不会根据锁的年龄自动解锁。

旧版空锁或损坏的锁没有可核验的持有者，会在 capabilities 中返回 `available: false` 和恢复说明。已有任务及下载仍可查询；不要再次生成替代原任务。

1. 停止所有使用该 MV 数据目录的 Osmanthus 服务，包括其他终端、后台进程和另一台共用目录的电脑。旧锁没有 PID，程序无法代替你确认这一步。
2. 在 `mv-studio` 目录运行下列命令，将 `<MV数据目录>` 替换为实际数据目录的绝对路径。路径含空格时保留引号。

   ```text
   node recover-budget-locks.mjs --data "<MV数据目录>" --kind all --confirm-services-stopped
   ```

3. 工具会拒绝仍有活进程的锁，将旧锁隔离为 `.budget-lock.orphaned-<唯一标识>`，保留原内容。它不会删除、修改或重置任何任务 JSON、预算金额、结果文件或不确定提交状态。
4. 重新启动服务。仍为“不确定”的原任务必须先核对供应商；解锁不意味着该任务可以再次付费提交。

`--kind image`、`video`、`speech` 可只处理一种锁。不提供 `--confirm-services-stopped` 不执行恢复。正常运行的服务不应执行此维护命令。
